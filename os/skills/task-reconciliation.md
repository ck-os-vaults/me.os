# task reconciliation

**Bottom line:** Bring only meaningful cross-project progress into one concise Chief brief without copying routine project reports or creating another memory system.

**When to read this:** During an owner-approved reconciliation, as input to a Morning Brief, when the owner asks for a cross-project checkpoint, or after meaningful work finishes in another task. Do not use it for ordinary single-task summaries.

## procedure

1. Identify the main Chief task, the last visible reconciliation, and only active or recently changed work since that cutoff when the environment can list them. Otherwise use durable project status files and an owner-provided handoff, and name any task state that could not be reached.
2. Read compact status and final results instead of full transcripts. Capture material outcomes, confirmed decisions, blockers, owner questions, next actions and owners, and durable output locations.
3. Report duplicate work and conflicts. Never silently choose between contradictory claims.
4. Keep routine reporting with its project. Include a project only when it affects priorities, requires owner attention, changes shared context, or creates a cross-project dependency.
5. Report repository publication state when it matters. Reconciliation does not authorize commits, pushes, file edits, task creation, external messages, or follow-up execution.
6. Return one concise input for the Chief of Staff home base or Morning Brief:
   - what materially changed;
   - what is waiting on the owner;
   - confirmed next actions and owners; propose priorities only when requested;
   - durable records updated or still needing approval.

## recurring use

This workflow is not a separate user-facing report by default. Use it inside an accepted Morning Brief or another owner-approved checkpoint. If the owner's scheduler requires a separate background routine, keep it read-only, attach it to the persistent Chief of Staff home base when possible, stay silent when nothing material changed, and do not create a new task per run.

Use only sources available to the chosen environment and any economical runtime capable of reliable summarization. Report missing task access or destination verification instead of simulating success.

## boundaries

Do not create a reconciliation log, dashboard, memory file, or parallel status system. Do not treat brainstorming, reviewer dissent, tentative recommendations, or unverified completion claims as durable decisions. Preserve links and locations instead of copying large outputs.
